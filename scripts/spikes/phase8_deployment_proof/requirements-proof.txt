# Phase 8 deployment proof — dependencies of the PROOF, not of the harness.
#
# The harness's own requirements.txt is untouched and must stay that way: `core/` works with
# no web framework at all and `tests/test_core_standalone.py` keeps proving it. Install this
# file into a separate virtualenv.
#
# Directly required (3):
#   litestar  2.24.0   ASGI, routing, CSRF, server-side sessions, multipart, test client
#   jinja2    3.1.6    server-rendered templates (litestar ships the binding, not the engine)
#   uvicorn   0.53.0   ASGI server
#
# Everything else below is transitive. Worth noting what `pip install litestar` alone drags
# in: httpx, msgspec, rich, rich-click, click, Pygments, markdown-it-py, polyfactory, Faker,
# PyYAML, litestar-htmx, multidict. Faker and polyfactory are test-data libraries and arrive
# as hard dependencies — a real cost to weigh against the built-ins Litestar provides.
#
# Deliberately NOT here:
#   cryptography   only needed for litestar's CLIENT-side sessions. Server-side sessions are
#                  the right choice anyway (the cookie carries an opaque id, nothing else),
#                  and cryptography has no wheel for Windows ARM64 — it cannot be built on
#                  this development machine at all. Avoiding it removed a blocker rather
#                  than a feature.
#   celery / redis / rq / kombu / dramatiq / arq / huey — no broker, no worker fleet.
